## Этап 2. Аутентификация

- [x] **AUTH-001** — Регистрация (backend)

  Эндпоинт регистрации: принимает ФИО, дату рождения, логин, пароль, номер телефона, телеграм. Валидация пароля (8–64 символа, латинские строчные и заглавные буквы, цифры, спецсимволы) и формата остальных полей — без подтверждения номера и телеграма.

- [ ] **AUTH-002** — Вход пользователя (backend)

  Эндпоинт входа по логину/паролю, выдача JWT в httpOnly cookie без refresh-токена (TTL — сутки).

- [ ] **AUTH-003** — Вход для сотрудников (backend)

  Отдельный эндпоинт входа по коду с телефона (дефолтный код "123456"). Если в БД нет ни одного пользователя — первый зарегистрированный автоматически становится сотрудником.

- [ ] **AUTH-004** — Страница регистрации (frontend `/registration/`)

  Поля: ФИО, дата рождения, логин, пароль (с подсказкой требований к сложности), повторите пароль, номер телефона, телеграм. Отправка на AUTH-001.

  > Без подтверждения номера и телеграма — только валидация формата, осознанное решение для MVP.

- [ ] **AUTH-005** — Страница входа (frontend `/login/`)

  Поля: логин, пароль. Ссылки "Забыли пароль?" и "Нет аккаунта? Регистрация". Отправка на AUTH-002.

- [ ] **AUTH-006** — Страница входа для сотрудников (frontend `/loginWork/`)

  Поля: логин, код с телефона, пароль. Ссылки "Отправить код" и "Забыли пароль?". Отправка на AUTH-003.

- [ ] **AUTH-007** — Защита приватных маршрутов

  Middleware на бэкенде (проверка JWT из cookie) и route guard на фронтенде: неавторизованный не должен попадать на `/user/*` и `/employee/*`.

## Этап 3. Заявка и скоринг по выписке

- [ ] **APP-001** — Форма новой заявки (frontend `/user/new`)

  Поля: сумма, цель/причина кредита (свободный текст), телеграм (@username), актуальный телеграм-канал (@channel — обязательное поле, без него форма не отправляется), выписка из банка (загрузка файла), чекбокс согласия с политикой конфиденциальности. Кнопка "Запросить".

- [ ] **APP-002** — Эндпоинт создания заявки (backend)

  Приём данных формы и файла выписки, создание записи Application со статусом "в обработке".

- [ ] **STMT-001** — Парсинг банковской выписки

  При загрузке файл сразу парсится в структурированные данные (остаток, поступления, траты по категориям за 3 месяца). Сам файл не сохраняется — хранятся только структурированные данные.

- [ ] **STMT-002** — Расчёт скоринга по выписке

  Расчёт вклада в итоговую оценку на основе среднего остатка, регулярности поступлений, доли трат на необходимые товары. Формирует часть позитивных сигналов / факторов риска в ScoreResult.

- [ ] **APP-003** — Пороговая автообработка заявки

  После расчёта итоговой оценки сравнение с порогами из настроек сотрудника (EMP-002): если оценка ≤ порога авто-отклонения — статус "авто-отказано"; если оценка ≥ порога авто-одобрения — статус "авто-одобрено"; иначе заявка уходит в очередь сотрудника.

- [ ] **APP-004** — Список заявок пользователя (frontend `/user/my`)

  Таблица заявок пользователя: id, статус, сумма, итоговая оценка.

- [ ] **APP-005** — Детальная карточка заявки пользователя (frontend `/user/my?menu={id}`)

  Отображение: id заявки, запрошенная сумма, цель кредита. Блок "Рекомендации системы" — позитивные сигналы и факторы риска двумя списками. Блок "Психологический портрет заёмщика" — три метрики по шкале 0–10 (стабильность работы, финансовая грамотность, ответственность). Блок "Отчёт для кредитного комитета" — кнопка скачивания + дата последнего обновления. Итоговая оценка — спидометр "Благонадёжность (0–100)".

- [ ] **APP-006** — Настройки профиля пользователя (frontend `/user/settings` + backend)

  Редактируемые поля: ФИО, логин, телеграм, номер телефона, пароль (со сменой).

## Этап 4. Кабинет сотрудника

- [ ] **EMP-001** — Настройки профиля сотрудника (frontend `/employee/settings` + backend)

  Аналогично APP-006: ФИО, логин, телеграм, номер телефона, пароль.

- [ ] **EMP-002** — Настройка порогов автоматизации

  Часть `/employee/settings`, блок "Автоматизация": порог "авто-отклонение ≤ X" и порог "авто-одобрение ≥ Y". Backend хранит оба порога в БД (не хардкод), их использует APP-003.

- [ ] **EMP-003** — Список актуальных заявок (frontend `/employee/newApplication`)

  Таблица заявок, ожидающих решения сотрудника (не попавших под автообработку): id, статус, ФИО заёмщика, сумма, итоговая оценка.

- [ ] **EMP-004** — Список всех заявок (frontend `/employee/application`)

  Таблица всех заявок вне зависимости от статуса: id, статус, ФИО, сумма, итоговая оценка.

- [ ] **EMP-005** — Детальная карточка заявки сотрудника (frontend `/employee/application?menu={id}`)

  Тот же разбор, что и в APP-005 (рекомендации системы, психологический портрет, отчёт, спидометр), плюс кнопки "Одобрить" и "Отклонить".

- [ ] **EMP-006** — Эндпоинт решения по заявке (backend)

  Приём решения сотрудника (одобрить/отклонить), обновление статуса заявки — изменение сразу отражается в `/user/my` у заёмщика.

## Этап 5. Telegram-скоринг

- [ ] **TG-001** — Парсинг публичного Telegram-канала

  Получение сообщений канала через Telegram Bot API по адресу, указанному в заявке.

  > Если канал недоступен или закрыт — просто не учитывается в оценке, без отдельной обработки ошибки для пользователя.

- [ ] **TG-002** — Расчёт скоринга и психологического портрета по данным канала

  На старте — захардкоженный сценарий (заранее заданные позитивные сигналы, факторы риска, метрики портрета и текст отчёта для демо). Если будет время — реальный анализ лексики, частоты упоминаний работы, подписок на финансовые каналы (LLM+NER).

- [ ] **TG-003** — Интеграция telegram-сигнала в итоговую оценку

  Объединение сигнала из TG-002 с оценкой по выписке (STMT-002) в единый итоговый балл. Должно работать и в отсутствие telegram-сигнала (см. TG-001) — тогда используется только оценка по выписке.
