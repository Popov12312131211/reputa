# APP-006 — Настройки профиля пользователя (frontend `/user/settings`)

## Статус
Выполнено (frontend-часть). Бэкенд не реализован — поля из моков, действия кнопок — заглушки.

## Что сделано (frontend)
- Создан `frontend/src/components/UserSettings.jsx` — страница настроек `/user/settings`:
  - Блок «Основная информация» — сетка полей 2×2 (ФИО, Логин, Телеграм, Номер телефона), у каждого поля справа иконка-карандаш.
  - Блок «Безопасность» — поля «Пароль» и «Повторите пароль» в один ряд с ОДНОЙ общей иконкой редактирования.
  - Все инпуты изначально read-only (блёклый текст, `readOnly`), клик по карандашу переключает конкретное поле (или пару пароля) в редактируемое состояние через локальный `state`; повторный клик возвращает в read-only.
  - Текущие значения — мок (`MOCK_PROFILE`), реального сохранения на бэкенд нет.
  - Кнопки «Удалить аккаунт» и «Выйти из аккаунта» в один ряд во всю ширину, в предупреждающем стиле (приглушённый красный/розовый фон + более тёмный текст того же оттенка); обработчики — `console.log`-заглушки.
- Создан `frontend/src/components/UserSettings.css` — выровненные инпуты (одинаковая высота 48px и внутренние отступы, подписи на одной горизонтали, иконки одного размера по вертикальному центру) по стилю существующих страниц (палитра/токены из `EmployeeSettings`/`Registration`).
- `frontend/src/App.jsx` — маршрут `/user/settings` переведён с `PlaceholderPage` на `UserSettings`.
- `frontend/src/locales/ru.json` — добавлен namespace `userSettings` (весь текст через i18n).

Сайдбар (COMP-001) не переделывался — подключён через существующий `Layout`/`Sidebar`.

## Доработка: приведение к поведению страницы регистрации
- Общая иконка редактирования пары паролей вынесена из инпута — отдельный элемент под парой полей (`usersettings-password__pencil`), права поля визуально одинаковые.
- В оба поля пароля добавлен глаз «показать/скрыть» (как в `Registration.jsx`), независимый переключатель на каждое поле; показывается только в режиме редактирования.
- Под полем «Пароль» подсказка требований сложности (`PASSWORD_RULES` из `constants/auth.js`) с живыми галочками — только в режиме редактирования.
- Валидация ФИО/Логин (непустые), Телеграм (`TELEGRAM`-формат, авто `@`), Номер телефона (маска +7(XXX)XXX-XX-XX и ограничение цифр) — переиспользована общая логика: вынесены `formatPhone`/`phoneIsValid`/`requiredIsValid` в новый `frontend/src/utils/validators.js`, `Registration.jsx` теперь импортирует их оттуда (свои локальные копии удалены).
- Несохранённые изменения: `dirty` = отличие `values` от снимка `savedValues`; при `dirty` — фиксированная кнопка «Сохранить» (правый нижний угол, не перекрывает контент за счёт нижнего отступа страницы). Сохранение — заглушка (`console.log` + обновление снимка).
- Защита от ухода: `beforeunload` (закрытие/обновление вкладки) + `useBlocker` (свой confirm-диалог при навигации по роутеру). Веб-маршрутизация переведена на data router: `main.jsx`/`App.jsx` используют `createBrowserRouter` + `RouterProvider` (`useBlocker` работает только под data router).
- Отмена правок: повторный клик по карандашу поля (или внешнему карандашу пароля) возвращает значение к сохранённому снимку.
