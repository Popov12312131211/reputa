## Статус

## Что сделано
- `frontend/src/components/EmployeeNewApplication.jsx` + `.css` (по образцу `UserMy.jsx`, APP-004):
  - Заголовок «Актуальные заявки» сверху (`employeeNewApplication.title`).
  - Карточка-таблица с колонками: ID, Статус, ФИО заёмщика, Сумма, Дата отправки, Итоговая оценка (по спецификации EMP-003 + дата).
  - Поле поиска по ФИО над таблицей (иконка `Search`, кнопка-крестик очистки при непустом запросе): фильтрация по подстроке без учёта регистра.
  - Сортировка по Дата отправки (по умолчанию — вверху самые старые, `created_at` asc), Сумма и Итоговая оценка (по возрастанию/убыванию).
  - Бейдж статуса — та же иконография/цвета, что в `/user/my` (`STATUS_GROUP` из `constants/application.js`); для всех строк очереди это «в обработке».
  - Пустые состояния: «Заявок в очереди пока нет» и «По вашему запросу ничего не найдено» для поиска без совпадений.
  - Стили — зеркало `UserMy.css` с префиксом `empnewapp-` + стили поля поиска.
- **Страница показывает только заявки «на рассмотрении»** (`Application.status == in_queue`): решённые (одобренные/отклонённые) отфильтровываются сразу в `visible`-мемо — ни из реального ответа, ни из мока они не попадают в таблицу и карточку этого маршрута.
- `frontend/src/components/App.jsx` — маршрут `/employee/newApplication` подключён к странице (вместо заглушки `PlaceholderPage`).
- `frontend/src/locales/ru.json` — namespace `employeeNewApplication` (все строки через i18n). Обновлённое мок-хранилище дополняет namespace `employeeApplicationDetail` ключом `decidedAt` (дата решения в карточке).

## Данные / заглушка
- Backend-эндпоинт очереди заявок сотрудника отсутствует (в `app/routers/employee.py` только настройки порогов).
- Общее хранилище mock-заявок вынесено в `frontend/src/mocks/employeeApplications.js` (было два независимых массива `MOCK_APPLICATIONS` в `EmployeeApplication.jsx` и `EmployeeNewApplication.jsx` — очищены):
  - Экспортируется единый массив `mockApplications` с литеральными статусами `'pending' | 'approved' | 'rejected'`; для UI/API-вида записи приводятся функцией `toEmployeeApplication`.
  - 8 заявок: 4 «на рассмотрении» (`pending`), 2 одобренные, 2 отклонённые — данные общие для обеих страниц.
  - Каждая запись: `id` (10 символов), `full_name`, `amount`, `purpose`, `status`, `score` (0–100), `created_at`, `positive_signals`, `risk_factors`, `portrait` (оценки портрета 0–10), `report` (путь к файлу отчёта, `updated_at`, история скачиваний `downloads: [{ date, id }]`).
  - Для решённых заявок: `decided_by` — `{ full_name, login, decided_at }` (у `pending` — `null`); в карточке выводятся как «Решение принял» и «Дата решения».
- `EmployeeNewApplication.jsx` и `EmployeeApplication.jsx` при монтировании пытаются получить `GET /api/employee/applications`; при отсутствии/ошибке показывают общий mock (через `mockApplications.map(toEmployeeApplication)`). `ApplicationDetailModal` при недоступности карточки на реальном API подставляет ту же заявку из mок-хранилища (`toEmployeeApplication`) и инициализирует историю скачиваний из `downloads` (новые записи добавляются при фактической выгрузке файла отчёта).
