## Что сделано
- `frontend/src/components/EmployeeApplication.jsx` + `.css` (новые) — страница `/employee/application` по образцу `UserMy.jsx` (APP-004) + поиск:
  - Заголовок «Все заявки» сверху (`employeeApplication.title`).
  - Карточка-таблица с колонками: ID, Статус (с фильтром по статусу аналогично `/user/my`: Все / В обработке / Одобрено / Отклонено), ФИО заёмщика, Сумма, Дата отправки, Итоговая оценка.
  - Два поля поиска над таблицей: поиск по ФИО (подстрока без учёта регистра) и поиск по ID заявки (`Hash`-иконка). Кнопка-крестик очищает оба поля разом.
  - Сортировка по Сумме, Дате отправки и Итоговой оценке (по возрастанию/убыванию).
  - Бейдж статуса — иконография/цвета из `constants/application.js` (`STATUS_GROUP`), как в `/user/my`.
  - Пустые состояния: «Заявок пока нет» и «По вашему запросу ничего не найдено» (при недоступности API показывает общий mock, как EMP-003).
  - Стили — зеркало `UserMy.css` с префиксом `empapp-` + расширенный блок поиска на два поля (на мобильном складывается в столбик).
- `frontend/src/components/EmployeeNewApplication.jsx` + `.css` — добавлен поиск по ID заявки рядом с существующим поиском по ФИО (как в списке всех заявок).
- `backend/app/routers/employee.py` — новый `GET /employee/applications`: возвращает ВСЕ заявки всех заёмщиков (новые сверху), `full_name` подтягивается из связанной таблицы `users`.
- `backend/app/schemas/application.py` — новый `ApplicationListItemResponse` (наследник `ApplicationResponse` + `full_name`).
- `backend/tests/test_employee_applications.py` (новый) — 4 теста: отдача всех заявок с `full_name`, пустой список, 401 для роли «пользователь», 401 без cookie.
- `frontend/src/App.jsx` — маршрут `/employee/application` подключён к странице (заглушка `PlaceholderPage` убрана).
- `frontend/src/locales/ru.json` — namespace `employeeApplication`, + ключи `idSearch`/`idPlaceholder` в `employeeNewApplication` (все строки через i18n).
