# Выполнение AUTH-007 — Защита приватных маршрутов

## Дата
2026-09-05

## Что сделано
- Backend: JWT-функции на PyJWT (`create_access_token`/`decode_access_token`), HTTP-middleware, защищающий `/user/*` и `/employee/*` по JWT из cookie с проверкой роли, dependency `get_current_user`, эндпоинт `GET /auth/me`, константы cookie/сообщения.
- Frontend: AuthContext загружает сессию через `/api/auth/me`; новый route guard `RequireAuth` (неавторизованный → `/login`, чужая роль → кабинет своей роли); в `App.jsx` guard оборачивает приватные маршруты.
- Прокси: vite + nginx срезают префикс `/api`, чтобы контракт `/api/auth/me` доходил до бэкенда `/auth/me` (задокументированный в AUTH-005/006 контракт, ранее несовместимый с роутерами без `/api`).
