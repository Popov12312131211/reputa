# EMP-005 — Детальная карточка заявки сотрудника (переиспользуемый компонент)

## Дата
2026-09-06

## Статус
Выполнено (включая рефакторинг под переиспользуемый компонент).

## Что сделано
### Бэкенд
- `GET /employee/applications/{application_id}` (`backend/app/routers/employee.py`):
  - проверяет роль сотрудника (middleware `main.py` + `get_current_user`),
  - фильтрует заявку только по id (сотруднику видна любая заявка любого заёмщика), несуществующая — 404,
  - возвращает `full_name` заёмщика, полный разбор скоринга `score_result` (сигналы, факторы риска, три метрики портрета 0–10, отчёт + дата обновления) и `decided_by_employee` — ФИО и логин сотрудника, принявшего решение. Схемы: `EmployeeApplicationDetailResponse` (+ `ScoreResultResponse`, + `EmployeePublic`) в `backend/app/schemas/application.py`.
  - Пока STMT-002/TG-003 не заполнил `ScoreResult`, поле `score_result` равно `null` — карточка показывает empty-состояние; до решения `decided_by_employee` равен `null`, после — данные сотрудника.
- Связь «заявка → сотрудник»: колонка `Application.decided_by` (FK `users.id`, nullable) + relationship `decided_by_user` в `backend/app/models/application.py`; у `user`-relationship явно задан `foreign_keys` (две FK на users.id). Миграция `backend/alembic/versions/0005_add_application_decided_by.py`.
- `POST /applications/{id}/decision` (`backend/app/routers/applications.py`, EMP-006) заполняет `decided_by = current_employee.id`.
- Тесты: `backend/tests/test_applications.py` (решение фиксирует сотрудника) и `backend/tests/test_employee_applications.py` (+decided_by_employee есть/отсутствует).

### Фронтенд
- Новый переиспользуемый компонент `frontend/src/components/ApplicationDetail.jsx` + `ApplicationDetail.css` (префикс `appdetail-`).
  - Шапка (статус, id, ФИО, «Запрос: {сумма} ₽», крестик) — как было, без изменений.
  - «Цель кредита» — выделенный контурный контейнер (`appdetail-purpose`).
  - «Рекомендации системы» — две колонки: позитивные сигналы — зелёные бейджи с галочкой (`Check`), факторы риска — янтарные бейджи с предупреждением (`AlertTriangle`).
  - «Психологический портрет заёмщика» и «Отчёт для кредитного комитета» — две колонки бок о бок (`appdetail-columns`) выше блока «Итоговая оценка».
  - «Отчёт»: кнопка «Скачать отчёт для банка» (формирует `.txt` из `report_content`) + блок «История скачиваний» — локальный лог записей «– {дата} {ID…}» (mock-состояние; бэкенд-эндпоинта хранения скачиваний нет).
  - «Итоговая оценка» — переиспользуемый `ScoreGauge`, без изменений.
  - Кнопки «Одобрить»/«Отклонить» → `POST /applications/{id}/decision`; после успеха карточка перезапрашивается (приходит `decided_by_employee`), статус в списке родительской страницы обновляется через `onDecided`.
  - После решения вместо кнопок — блок «Решение принято: …» + «Решение принял: {ФИО} ({login})».
  - loading/error/empty-состояния; Escape и блокировка прокрутки — внутри компонента.
- `frontend/src/components/EmployeeApplication.jsx` (`/employee/application`) и `frontend/src/components/EmployeeNewApplication.jsx` (`/employee/newApplication`) — подключают один и тот же `ApplicationDetailModal` по `?menu={id}`; в обеих таблицах кликабельные строки (мышь/Enter/пробел), строки `empapp-`/`empnewapp-` CSS-наворки из-под модалки убраны.
- i18n — namespace `employeeApplicationDetail` в `frontend/src/locales/ru.json`: обновлён текст кнопки, добавлены `downloadHistory`, `downloadHistoryEmpty`, `decidedBy`.
