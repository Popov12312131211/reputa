# APP-005 — Детальная карточка заявки пользователя (frontend `/user/my?menu={id}`)

## Статус
Выполнено для пользовательской зоны (APP-005). Итоговая оценка — спидометр из переиспользуемого компонента `ScoreGauge`. Спидометр в репозитории ранее не существовал (см. «Блокеры»), поэтому он создан как переиспользуемый компонент и будет общим с EMP-005.

## Что сделано
- Бэкенд-эндпоинт `GET /user/applications/{application_id}` (`backend/app/routers/user_applications.py`):
  - проверяет JWT-сессию через `get_current_user` (middleware из `main.py` защищает `user`-роль, `routers/user_applications.py` — дополнительно в `routers/user_applications.py`),
  - фильтрует заявку и по `id`, и по `user_id` текущего пользователя → чужая/несуществующая заявка возвращает **404** (не раскрывает существование чужих заявок, эквивалент защиты 403),
  - ответ включает `full_name` заёмщика (для шапки карточки) через новую схему `ApplicationDetailResponse`.
- Модальное окно поверх `/user/my`, управляется query-параметром `menu` и закрытием по Esc/оверлею/крестику.
- Карточка содержит ровно 3 смысловых блока по спецификации:
  1. Шапка в одну строку: иконка статуса (та же иконография/цвета, что в таблице APP-004), полный ID заявки, ФИО, «Запрос: {сумма} ₽».
  2. «Цель кредита» — read-only textarea с причиной.
  3. «Итоговая оценка» — спидометр «Благонадёжность (0–100)».
- Аналитика заёмщику НЕ отдаётся и НЕ показывается (позитивные сигналы, факторы риска, психологический портрет, отчёт для комитета) — только сотруднику в EMP-005.
- Данные получаются с бэкенда по id; в случае его временной недоступности/ошибки подставляется строка из уже загруженного списка (мок APP-002), чтобы карточка не ломалась.
