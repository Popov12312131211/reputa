## Дата

## Что сделано
- Пороги автообоработки перенесены с общего синглтона `threshold_settings` (id=1) на персональные пороги сотрудников — новая таблица `employee_thresholds` (`user_id` = FK `users.id` и первичный ключ, «один сотрудник — одна строка»). Модель `EmployeeThresholds` в `models/employee_thresholds.py`; свойство `id` == `user_id` сохранено, чтобы ответ `/api/employee/settings` не изменил форму.
- Миграция `0006_employee_thresholds.py`: создаёт `employee_thresholds`, переносит значения прежней строки-синглтона (30/70 или актуальные из БД) как дефолты в записи всех существующих сотрудников, удаляет старую таблицу `threshold_settings`. Цепочка миграций линейна, head = 0006.
- `services/auto_processing.py`:
  - `get_threshold_settings` заменён на `get_employee_thresholds(db, employee)` — читает персональные пороги сотрудника, при отсутствии создаёт дефолты (страховка для пустой БД);
  - `decide_auto_status` — без изменений (чистая функция по порогам одного сотрудника);
  - `apply_auto_decision` переписан под APP-008: после расчёта оценки берёт сотрудников в случайном порядке (`random.shuffle`) и проверяет, подпадает ли рейтинг заёмщика под персональные пороги очередного сотрудника:
    - подпадает — заявка закрывается автоматически, а `Application.decided_by` фиксирует сотрудника, закрывшего сделку;
    - не подпадает — следующий случайный сотрудник;
    - не подошёл ни один — статус `in_queue`, `decided_by` не заполняется (заявка остаётся видимой любому сотруднику, EMP-003/EMP-004).
  - Без оценки (`score=None`) статус не трогается (как раньше).
- `routers/employee.py`: `GET/PUT /employee/settings` читают/обновляют пороги текущего сотрудника (API сохранено — фронтенд EMP-002 не менялся).
- `core/constants.py`: убран неактуальный `THRESHOLD_SETTINGS_ID`, комментарий блока порогов обновлён; дефолтные пороги остались и стали значениями по умолчанию для новых/отсутствующих записей сотрудника.

## Доработки по итогам ревизии
- `apply_auto_decision`: уже решённые заявки (статус не `in_queue`) не трогаются — возвращается текущий статус; при уходе в `in_queue` `decided_by` сбрасывается (убран stale от прошлого прогона).
- Детерминированный порядок перебора: `rng`-параметр (дефолт — `random`), базовый порядок — `order_by(User.id)`; комментарий про «копию списка» исправлен.
- Тесты: guard уже решённой заявки, сброс stale-`decided_by`, победитель при двух матчирующихся сотрудниках через stub-rng.
- Проверка: `pytest -q` в `backend/` → **201 passed**; alembic head = 0006. Новых ошибок не найдено.
