## Что сделано
- Пороги авто-одобрения/авто-отказа больше не в коде: хранятся в БД в таблице `threshold_settings` (синглтон, id=1). Модель `ThresholdSettings` + Alembic-миграция `0004` (create + seed дефолтной строки 30/70). Редактирование через сотрудника будет в EMP-002, здесь — только хранение и чтение.
- Константы: `AUTO_REJECT_THRESHOLD_DEFAULT=30`, `AUTO_APPROVE_THRESHOLD_DEFAULT=70`, `THRESHOLD_SETTINGS_ID=1`.
- Сервис `services/auto_processing.py` — «слой поверх итоговой оценки»:
  - `decide_auto_status(score, settings)` — чистая функция: `score ≤ порог авто-отклонения` → `auto_rejected`; `score ≥ порог авто-одобрения` → `auto_approved`; иначе → `in_queue` (в очередь сотрудника).
  - `get_threshold_settings(db)` — чтение синглтона; при отсутствии строки создаёт дефолты (страховка для пустой БД).
  - `apply_auto_decision(db, application)` — применяет решение к заявке после расчёта оценки; при `score=None` статус не меняется.
- Точка вызова — пайплайн скоринга (STMT-002/TG-003), на момент задачи не существующего; сервис готов к подключению.
