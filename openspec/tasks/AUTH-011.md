# AUTH-011 — Frontend: страница регистрации сотрудников

## Статус
Выполнено (фронтенд). Ожидает AUTH-010 (backend-эндпоинт регистрации сотрудника).

## Что сделано
- Компонент `RegistrationWork.jsx` + `RegistrationWork.css` на базе стилей Registration/LoginWork.
- Все поля регистрации заёмщика (ФИО, дата рождения, логин, пароль с подсказкой требований, повторите пароль, номер телефона, телеграм) + дополнительное обязательное поле «Идентификатор» в начале формы (после ФИО).
- Валидация идентификатора на фронте до отправки: регэксп `^[A-Za-z][0-9]{3}room19$` (одна англ. буква + 3 цифры + literal "room19"). Класс и паттерн вынесены в `constants/auth.js` (`EMPLOYEE_IDENTIFIER`).
- Поведение поля «Идентификатор»:
  - Ограничение длины по вводу соответствует полной длине — 1 + 3 + 6 = 10 символов (`maxLength="10"` и `format` со `slice(0, 10)`), чтобы пользователь мог допечатать "room19" целиком.
  - Валидация формата срабатывает только на потерю фокуса / попытку submit (через `touched`), не блокирует и не обрезает ввод посимвольно — промежуточное значение, временно не соответствующее финальному формату, вводить можно.
  - Постоянная подсказка формата убрана. При невалидном непустом значении показывается короткое сообщение «Неверный формат» (`identifierError`), на пустом поле — краткое «Обязательное поле» (как у остальных полей).
- Клиентская валидация остальных полей — та же, что на `/registration` (fullName >= 3 слов, дата 18+, телефон по маске, telegram @username, пароль по PASSWORD_RULES, пароли совпадают).
- Отправка — на эндпоинт `POST /api/auth/register/employee` (AUTH-010). Поле идентификатора передаётся как `identifier`.
- При успехе — редирект на `/loginWork` (вход для персонала).
- Маршрут `/registrationWork` в `App.jsx` подключён к компоненту `RegistrationWork`.
- Строка «Нет аккаунта? Регистрация» на странице входа для персонала (`LoginWork.jsx`) теперь ведёт на `/registrationWork` (переход на регистрацию сотрудника — только через страницу входа для персонала).
- Все строки интерфейса в i18n (namespace `registrationWork` в `ru.json`); маршрут добавлен в `routes`.
