# EMP-001 — Настройки профиля сотрудника (frontend `/employee/settings`)

## Статус
Выполнено (frontend-часть). Бэкенд профиля не реализован — поля из моков, действия кнопок — заглушки. Блок «Автоматизация» — реальная логика EMP-002.

## Что сделано
- `frontend/src/components/EmployeeSettings.jsx` переписан по образцу `UserSettings.jsx` (APP-006) — тот же паттерн «редактируемые настройки» построчно:
  - Блок «Основная информация» — сетка полей 2×2 (ФИО, Логин, Телеграм, Номер телефона), у каждого поля справа иконка-карандаш; повторный клик возвращает значение к сохранённому снимку.
  - Блок «Безопасность» — поля «Пароль» и «Повторите пароль» в один ряд с ОДНОЙ общей иконкой редактирования; глаз показать/скрыть — только в режиме редактирования; подсказка требований сложности пароля всегда видна; в одном блоке кнопки «Удалить аккаунт» и «Выйти из аккаунта» (заглушки `console.log`).
  - Блок «Автоматизация» — идёт ПОСЛЕ блока «Безопасность»; переиспользована реальная логика EMP-002: чтение/сохранение порогов через `GET/PUT /api/employee/settings`, клиентская валидация 0–100 и reject < approve.
  - Текущие значения профиля — мок (`MOCK_PROFILE`), сохранение — заглушка (снимок `savedValues` + `console.log`).
  - Несохранённые изменения: `dirty` = отличие `values` от `savedValues`; при `dirty` — фиксированная кнопка «Сохранить» в правом нижнем углу; валидация только изменённых (dirty) полей.
  - Защита от ухода: `beforeunload` + `useBlocker` (свой confirm-диалог), как в UserSettings.
- `frontend/src/components/EmployeeSettings.css` — зеркало `UserSettings.css` с префиксом `employeesettings-` + стили блока «Автоматизация» (инпуты `--auto` и форма порогов).
- `frontend/src/locales/ru.json` — namespace `employeeSettings`: добавлены ключи профиля/безопасности/подтверждения (по типу `userSettings`); `save` для подвала автоматизации переименован в `saveThresholds` (чтобы не конфликтовать с кнопкой «Сохранить» профиля).
