## Что сделано

- Добавлена зависимость `PyJWT==2.10.1` (`requirements.txt`).
- В `app/core/config.py` добавлены настройки cookie: `ACCESS_TOKEN_COOKIE_NAME`, `COOKIE_SECURE` (по умолчанию false, включать только за HTTPS). В `.env.example` — комментарий про `COOKIE_SECURE`.

- В `app/services/auth.py` добавлена `create_access_token(user)` — JWT с `sub` (id пользователя), `role`, `iat`, `exp` на основе `settings.JWT_EXPIRE_MINUTES`.

- В `app/routers/auth.py` добавлен `POST /auth/login`: поиск пользователя по логину, проверка пароля, выдача JWT в httpOnly cookie (samesite=lax, path=/, max_age = сутки), ответ — данные пользователя.

## Дополнение: сквозная проверка в Docker + баг `.dockerignore`

Выполнен сквозной сценарий в Docker (`docker compose up --build -d`):

- `GET /health` → `{"status":"ok","database":"connected"}`.
- `POST /auth/register` → **201**.
- `POST /auth/login` → **200** + `Set-Cookie: access_token=...; HttpOnly`, TTL ровно 24 ч.
- неверный пароль → **401** `{"detail":"Неверный логин или пароль"}`.

Найден и исправлен баг: в `backend/.dockerignore` было исключено `alembic/versions` — файлы миграций не попадали в Docker-образ, поэтому `alembic upgrade head` в entrypoint не находил скриптов и контейнерная БД оставалась без таблиц (запросы падали с `relation "users" does not exist`). Из `.dockerignore` строка `alembic/versions` удалена, backend пересобран. После пересборки `alembic current` → `0003 (head)`.

Передаётся дальше: локальный uvicorn на Windows подключался к локальному Windows-PostgreSQL (PID 7312), занимающему `5432` вместе с контейнером — при разработке вне Docker не забыть про этот конфликт либо переназначить порт.
